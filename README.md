# 乡镇卫生院家庭病床申请巡诊耗材医保结算平台

面向乡镇卫生院的家庭病床一体化平台：**家属申请 → 家庭医生六要素评估 → 可解释排班 → 护士上门执行（体征/压疮/换药/导尿/血糖血压/用药/家属签字）→ 耗材缺货替代确认（原医嘱/替代规格/医保差异/可能影响 → 医生确认 → 家属签字 → 执行 → 后续伤口照片持续追踪；拒绝则自动补货并调整本次护理计划）→ 医生调处方/复诊/转诊（远程复核）→ 护理+耗材+冷链统一账单（医保/自费一单清）→ 医保合规审查 → 全链可还原**。

技术栈：Vue 3 + Vite + Element Plus + Pinia + ECharts；Spring Boot 3.3 + Spring Security/JWT + JPA；PostgreSQL 15；Docker Compose 一键启动。

## 一、快速启动（Docker Compose，推荐）

```bash
docker compose up -d --build
```

- 前端：http://localhost:8088
- 后端 API：http://localhost:8080
- Swagger UI（OpenAPI 3 文档）：http://localhost:8080/swagger-ui.html
- PostgreSQL：localhost:5432（homebed/homebed123）

首次启动后端会自动建表并写入演示数据（9 个测试账号、4 名患者、申请/评估/计划/已完成巡诊/医嘱/风险事件/一张含合规初审结果的演示账单，以及 5 张耗材缺货替代确认单+2 条补货任务+护理计划调整）。

停止：`docker compose down`（保留数据加 `-v` 之外默认保留卷；清空数据用 `docker compose down -v`）。

## 二、本地开发启动


## 四、建议的业务验证路径

1. **家属** 登录 → “建床申请”为老人提交申请（勾选护理需求）。
2. **家庭医生** 登录 → 对申请评估：病情/距离（可按坐标自动测算）/照护人/医保资格/护理项目频次/风险等级 → 批准建床或驳回。
3. **管理者** → “巡诊计划排班”选择批准单 → **智能排班**：查看三名护士在技能匹配、本周负荷、路线聚集、半径红线上的打分，以及“为什么是她、为什么不是别人”的可解释说明与基层约束权衡（系统自动生成 4 周上门任务）。
4. **护士** → “上门巡诊”对待办任务**签到上门** → 填写体征、压疮/换药/导尿/用药记录、勾选护理收费项、领用耗材（冷链药品登记交接温度）、上传现场照片、采集**家属手写签字**后提交。
   - 可验证异常：上报“家属不在家/耗材缺货/患者住院”等，任务自动挂起；管理者在“巡诊异常”中改期/改派恢复。
   - 可验证风险：血压 ≥180/110、血氧 <92%、冷链温度越界等会**自动生成风险事件**。
5. **耗材缺货替代确认**（菜单“缺货替代确认”，护士/医生/家属/管理者均可见，按角色操作）：
   - 护士在患者李长顺的上门任务中发现**藻酸盐伤口敷料缺货（库存 0）**，发起替代申请；平台固化并展示 **①原医嘱（YZ20260927001 继续使用藻酸盐敷料）②替代材料规格 ③医保报销差异（甲类/乙类/丙类、报销比例、总费用/医保/自费差额，申请时快照）④可能影响（愈合变慢/黏胶过敏/自费变化）**。
   - **医生确认** → **家属手写签字**：
     - 预置单 `TD20260929001`（藻酸盐→水胶体，乙类→甲类，自费 11.20→1.80）：家属同意→护士执行出库→后续上门上传伤口照片追踪，判定“愈合正常”；
     - 预置单 `TD20261002002`（藻酸盐→自粘泡沫敷料，乙类→**丙类全自费**）：执行后追踪先“愈合变慢”后“出现过敏”，**自动生成 MEDIUM/HIGH 风险事件**；上级医生周敏**回看替代原因**后停用替代品、安排原品到货换回，并自动生成“调整护理方案”医嘱；
     - `TD20261005003` 待医生确认、`TD20261005004` 医生已确认待家属签字——可现场走通“医生确认→家属同意/拒绝”两种分支；
     - 家属**不同意**（预置单 `TD20261005005` 导尿包→硅胶导尿包，家属坚持原品）：系统**自动生成原品补货任务**（下单/催货→到货入库增加库存）并**调整本次护理计划**（本次会阴护理+通畅度评估，原品到货 24 小时内补做），补做完成后补货任务联动闭环。
   - 替代执行后每次上门可继续在确认单中**上传伤口照片登记效果**；愈合变慢/过敏自动风险预警，医生可随时回看“为什么替代、家属是否签字、医保差多少”。
6. **家庭医生** 在巡诊记录中**下达医嘱**（调整处方/复诊/转诊）→ 用 `doctor2` 登录“医嘱与远程复核”完成**另一名医生远程复核**。
7. **财务** → “统一账单”按账期生成：护理服务、耗材领用（含缺货替代出库行，行备注含替代单号/原品/医生与家属签字/医保差异）、冷链药品合并为一单，自动拆分医保报销与家属自费；同来源已出账不重复计入。
8. **家属** 打开账单逐行核对（每行可回溯到巡诊记录与出库流水）→ 确认，或点“对收费有疑问”发起**收费质疑**；财务可对照“服务全链还原”答复并剔除重算。
9. **医保经办** → “医保合规审查”：查看自动初审命中规则（R1 重复收费、R2 超频次、R3 无家属签字、R4 医保资格存疑、R5 冷链温度缺失、R6 目录变化按快照结算、R7 照片证据缺失、**R8 缺货替代材料：校验医生确认+家属签字并提示医保类别/比例/自费差异，可解释提示而非机械拒付**），给出复核结论后财务结算。
10. **收费/医保目录**（财务）对目录项执行“目录变更”：旧版本失效、新版本生效，历史账单不受影响（R6 会提示按出账快照还原）。
11. **管理者看板**：巡诊负荷与超时、上门半径分布与超半径患者、异常类型、风险分布、耗材消耗 Top 与缺货预警、**缺货替代各环节待办（待医生确认/待家属签字/追踪中/拒绝/已回看）与待补货数**、金额概览。
12. **服务全链还原**：选择任一建床申请，查看申请→评估→排班→每次上门（签到/体征/照片/耗材/异常/医嘱/家属签字/**缺货替代确认/替代追踪/补货/护理计划调整**）→账单→合规→风险的完整时间线证据。

### 演示数据中预置的冲突素材

- 患者李长顺同一天两次换药（晚间敷料渗湿补换）：合规初审自动命中 **R1 重复收费/超每日限次**，可由医保经办结合家属签字与照片判定“情况属实准予报销”——体现系统是**可解释提示**而非机械拒付。
- 一支门冬胰岛素领用**未登记冷链温度** → 命中 **R5**；登记温度越界则自动生成冷链风险事件。
- 患者孙桂英住在大岭村山后（约 6km，超出 5km 半径）且有 HIGH 风险与待处理血氧风险，排班解释中给出“同片区拼单、雨雪改期、家属须在场”的安排理由。
- **缺货替代三类对照素材**：水胶体（甲类、报销更高、追踪正常）、泡沫敷料（丙类全自费、追踪变慢→过敏→医生回看调整）、硅胶导尿包（家属拒绝→补货+本次护理计划调整→到货补做闭环）。

- 执行缺货替代端到端冒烟脚本 **37 个场景全部通过**（`scripts/smoke_substitute.py`，对 8080 真实 HTTP 调用）：
  - 5 张预置替代单状态正确（追踪正常/已回看过敏/待医生/待家属/拒绝补货）；原医嘱快照、医保差额（乙类→甲类自费 11.20→1.80）、医生确认与家属签字、追踪照片完整；

  - 账单合并替代出库行（总额 434.00 / 医保 305.60 / 自费 128.40），合规初审命中 **R1×3 + R5 + R8×2**，R8 提示含原品→替代医保类别差异与“医生确认/家属签字”链；
  - 服务全链还原时间线含“耗材替代/替代追踪/补货任务/护理计划调整”节点；巡诊详情携带替代单；看板替代/补货 KPI 正确。
- 历史冒烟链路保持原有结果：预置账单 R1×3、R5 命中、金额拆分口径未变（替代行新增后总额 434.00）。
- `npm run build`：前端生产构建通过（新增 `Substitutes.vue` 33.6 kB）；`npm run dev` 启动后首页 200、新页面经 Vite 编译 200，经代理登录后端并拉取家属可见替代单成功。

- Docker：已提供多阶段 Dockerfile 与 docker-compose.yml（当前沙箱无 docker 守护进程，未在本机执行镜像构建；部署环境执行 `docker compose up -d --build` 即可）。
